# Adrobot — обёртка над Keitaro

Веб-приложение для работы с рекламным трекером [Keitaro](https://keitaro.io) через Admin API.

1. **Создаватор кампаний.** Название + гео + оффер → кампания с двумя потоками:
   поток 1 ловит указанные страны и отправляет на Google, поток 2 отправляет остальной трафик на оффер.
   Домен, группа, источник, ротация «по позиции» и CPC-модель затрат подставляются автоматически.
2. **Редактор кампании.** Потоки, офферы с долями трафика, клики/уники/боты за период.
   Можно добавлять и удалять офферы.

Стек: **FastAPI**, **SQLAlchemy 2.0 (async)**, **Alembic**, httpx. Фронтенд — HTML + CSS + ES-модуль без сборки,
раздаётся самим FastAPI.

## Запуск

Нужен Python 3.11 или новее. Проверьте версию: `python3 --version`.
Если она старше (на macOS системный Python бывает 3.9), поставьте новый через Homebrew: `brew install python@3.12`.

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env                 # впишите KEITARO_API_KEY (кнопка «API ключ» в эмуляторе) и CAMPAIGN_PREFIX
alembic upgrade head                 # миграции (по умолчанию SQLite: ./adrobot.db)

uvicorn app.main:app --reload
```

После `source .venv/bin/activate` в начале строки терминала появится `(.venv)`. Дальше в этом окне
`python` и `pip` уже работают как надо. Если Homebrew поставил `python3.12`, а `python3` указывает на старую версию,
создавайте окружение командой `python3.12 -m venv .venv`.

**Windows (PowerShell)**

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000. Swagger: http://127.0.0.1:8000/docs.

**Настройки (`.env`)**

| Переменная | Назначение |
|---|---|
| `KEITARO_BASE_URL` | Адрес Keitaro без `/admin` |
| `KEITARO_API_KEY` | Ключ: Keitaro → Профиль → API ключи |
| `KEITARO_DOMAIN`, `KEITARO_GROUP`, `KEITARO_SOURCE` | Имена домена, группы и источника для новых кампаний |
| `CAMPAIGN_PREFIX` | Например `test_ivanov_`. Добавляется к названию автоматически |
| `EDIT_ONLY_PREFIXED` | `true`: редактор видит и меняет только кампании с префиксом |
| `STATS_TIMEZONE` | Часовой пояс Keitaro. От него зависят «Сегодня» и «Вчера» |
| `DATABASE_URL` | По умолчанию SQLite. Для Postgres: `postgresql+asyncpg://…` и `pip install asyncpg` |

Секреты хранятся только в `.env` (он в `.gitignore`). В репозитории лежит `.env.example`.

## Тесты и проверки

## Архитектура

```
app/
├── main.py              точка сборки: клиент, БД, кэш, роуты, статика
├── config.py            настройки (pydantic-settings)
├── errors.py            доменные ошибки без привязки к FastAPI
├── api/                 HTTP-слой: роуты, схемы запросов, DI, формат ошибок
├── services/            сценарии: создание кампании, редактор, справочники
│   ├── ports.py         контракт Keitaro (Protocol), от него зависят сервисы
│   └── views.py         модели результатов, они же схемы ответов API
├── keitaro/             адаптер Keitaro: HTTP-клиент, модели ответов, тела запросов
├── db/                  ORM-модели, репозитории, UnitOfWork
└── domain/              чистые функции без I/O: доли, гео, периоды
migrations/              Alembic (async)
frontend/js/             ES-модули без сборки
├── main.js              вход, вкладки, маршрутизация по hash
├── api.js, dom.js       запросы и DOM-хелперы
├── combobox.js          автокомплит
├── create/, editor/     на каждый экран: view.js (чистые HTML-шаблоны) и controller.js (события, запросы)
└── format.js, geo.js, offers.js
```

Зависимости направлены внутрь: `api → services → keitaro / db`, а `domain` ни от чего не зависит.
Сервисы не знают ни про HTTP, ни про SQLAlchemy: Keitaro они видят через `KeitaroPort`,
базу через `UnitOfWork`.

### Принятые решения

- **Keitaro — источник правды.** Кампании, потоки и офферы хранятся там. Локальная БД хранит реестр
  созданных кампаний (`campaigns`) и журнал действий (`action_log`). Если запись в локальную БД
  не удалась, уже созданная в Keitaro кампания не откатывается.
- **Откат при частичном сбое.** Если кампанию создали, а поток не получился, кампания удаляется.
  Keitaro переносит удалённые кампании в архив, и название остаётся занятым.
- **Порядок потоков.** Ротация «по позиции», поэтому гео-поток создаётся первым.
- **Гео.** Можно указать несколько стран через запятую.
- **Доли офферов.** При любом изменении состава потока трафик делится поровну, сумма всегда 100%.
- **Удаление офферов.** Можно удалить любой оффер, в том числе последний: на тестовом аккаунте он
  единственный. Редактор просит усиленное подтверждение и предупреждает, что в потоке пусто.
- **Защита.** Редактор по умолчанию работает только с кампаниями с вашим префиксом.
- **Статистика.** Период считается на сервере в часовом поясе Keitaro (`STATS_TIMEZONE`).
  Итоговые «Уники» берутся из summary отчёта, а не складываются по потокам.
- **Повторное создание.** Кампания с тем же названием отклоняется (409); кнопка в UI блокируется
  на время запроса.
- **Фронтенд без сборки.** Два экрана и нативные ES-модули: сборщик не нужен, а проект запускается
  одной командой. Если интерфейс разрастётся, модули переносятся в Vite без изменения структуры.

### Стиль кода

- **Python:** ruff (линтер и форматтер, настройки в `pyproject.toml`), строки до 100 символов.
- **Комментарии:** только docstring. Python: Google-стиль, по умолчанию одна строка; секция `Raises:`
  только там, где исключение часть контракта. JS: JSDoc. Комментарии `#` и `//` не используются,
  а объяснение «почему» живёт в docstring.
- **Язык:** идентификаторы английские, docstring и сообщения для пользователя русские.
- **Модуль = ответственность:** у каждого файла docstring модуля, а у слоёв свой каталог.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta` | Префикс, домен, группа, источник |
| GET | `/api/offers?q=` | Поиск офферов для автокомплита |
| GET | `/api/campaigns?q=` | Список кампаний для редактора |
| POST | `/api/campaigns` | Создать кампанию `{name, geo, offer_id}` |
| GET | `/api/campaigns/{id}?range=today\|yesterday\|7d\|30d` | Потоки, офферы, статистика |
| POST | `/api/campaigns/{id}/streams/{stream_id}/offers` | Добавить оффер `{offer_id}` |
| DELETE | `/api/campaigns/{id}/streams/{stream_id}/offers/{offer_id}` | Удалить оффер |

## Проверено на эмуляторе Keitaro

Приложение прогонялось против учебного стенда `keitaro-for-tests.etolegko.com` (домен `kt-emulator.test`).
Результат сверялся с админкой эмулятора:

- создание кампании: домен, группа и источник `FORTESTS`, ротация «по позиции», CPC, кампания включена;
- потоки: первым гео-поток с фильтром «Страны принимать» и редиректом на google.com, вторым поток с оффером;
- добавление оффера (доли 50/50) и удаление (оставшийся оффер снова 100%): совпало с админкой.

Что выяснилось при проверке (в коде уже учтено, всё живёт в `app/keitaro/payloads.py` и `client.py`):

- `GET /groups` требует параметр `type`;
- при создании кампании обязателен `alias`;
- `action_type` обязателен у обоих потоков, в том числе у потока с офферами;
- «удаление» кампании в Keitaro отправляет её в архив, и её название остаётся занятым, поэтому при откате
  потоков повторное создание с тем же именем невозможно (приложение показывает понятное сообщение).

**Статистика.** Эмулятор отвечает 404 на `POST /report/build`. Редактор в этом случае всё равно открывает
кампанию с потоками и офферами, а вместо цифр показывает прочерки и пояснение, чтобы не выдавать нули
за настоящие данные. Разбор отчёта с данными (`stream_id` и метрики) проверен только на фейковом Keitaro.

## Ограничения и что можно доделать

- Поведение редактора из видео в ТЗ не сверялось (видео недоступно при разработке). Доли сейчас всегда равные.
  Ручное редактирование долей и вес потоков не реализованы.
- Параллельные правки одного потока двумя вкладками: побеждает последняя запись.
- Нет авторизации в самом приложении. Запускать нужно локально или за закрытым прокси.
- Dockerfile и CI пока нет.
- Фронтенд-контроллеры (работа с DOM) покрыты только ручной проверкой, автотесты есть для шаблонов и чистых функций.
